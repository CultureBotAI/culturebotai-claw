# EdgeMech supervisor metadata writer

Created 2026-11-28 for the explicitly authorized continuation of the existing
EdgeMech restart campaign and reconciliation of its three supervisor-owned files.
CLAW base: `5669421db46a6e6142479caecd761dc57928ac78`.

This helper does not inspect or control native agents, contact providers, read
credentials, edit native checkpoints, mutate Git, or grant scientific readiness.
Its only replacement targets are campaign `ACK.md`, campaign `progress.json`,
and the existing CLAW task descriptor `workspace/tasks/edgemech_restart_20261120.yaml`.
It retains a new exclusive dated checkpoint below the campaign root. Actual
private roots, session identities, candidate data and evidence stay in the private
reviewed plan and its beforeimages, not in this source or public Git history.

The explicit CLI takes real absolute CLAW/campaign roots, a private plan and the
independently reviewed SHA256 of that plan. `--apply` is absent by default. The
version1 plan contains a timestamp run ID and exactly three entries under `files`,
keyed by the fixed target basenames. Each entry supplies `target`, `candidate`,
`before_sha256` and `candidate_sha256`. Candidate JSON objects are parsed; the task
identity is fixed. Scientific content is approved by the independent data review,
not inferred or generated by this utility.

Before any mutation, repository identity and every original/candidate byte hash
must match. Apply repeats those checks under a short shared CLAW LockManager lease,
using the configured absolute workspace. It exclusively retains the exact plan,
all beforeimages, all candidates and intent before staging replacements. Each
target is checked again immediately before its atomic replacement and read back.
The three-file update is not globally atomic: any interruption or partial failure
retains beforeimages/staging and a failure receipt when the process can write one.
Never automatically retry a partly applied run or restore over a concurrent edit.
A crash before the success receipt requires explicit inspection, not a success claim.

Tests use synthetic private directories and mocked repository/lease adapters.
They cover read-only planning, exact application, stale originals, substituted
plans/candidates, forbidden destinations, symlinks, retained checkpoint refusal,
exclusive receipts and a partial replacement failure with lease release. No
live helper invocation is permitted until independent source and exact-data review.

Provenance: authored from the current supervisor metadata requirements, using
maintained RepositoryTarget, merged_repository_environment and LockManager APIs.
No historical recovery or source-restoration helper is replayed or rewritten.
The old branch-specific lease holders were inspected and left unchanged.

Validation before independent review:10 focused offline tests passed. Disabling
the beforeimage hash guard failed the distinguishing stale-original test in a
fresh pytest process. Removing exclusive creation failed the retained-receipt
test in a separate fresh process. Restored source passed all10 tests. No live
plan, downstream metadata replacement or native input was executed.
