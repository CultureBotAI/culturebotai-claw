# AssayMech admission and release dependencies

AssayMech is the public repository
[CultureBotAI/AssayMech](https://github.com/CultureBotAI/AssayMech). Its verified
initial main is the empty commit
`a85aea616168160ec7e5dc08e71f15b361455924`. The planned package is `src/assaymech`,
the LinkML schema is `src/assaymech/schema/assaymech.yaml`, and maintained assay
records belong under `data/assays/*.yaml`. Scaffold and seed records are separate
PRs; these declarations describe empty main, not prospective branch content.

Configure `ASSAYMECH_ROOT` only to an exact identity-verified worktree. Durable
clones, worktrees, review evidence and session state belong under
`~/agent-work/AssayMech/`; never retain session state in system temporary roots.
Push authorized commits the same day.

All implementation capabilities remain disabled or not applicable, with
recorded reasons. Mandatory `vendored_sync` is an authoritative-consumer
obligation rather than a claim of deployment. Shared serialization is unverified.
The exact 22 applicable missing paths are recorded in the bidirectional
`INCOMPLETE_CONSUMERS` ledger. Assay includes all three native contracts;
EdgeMech's exceptions are unchanged. The `validate-strict` workflow mapping is
prospective and does not activate remote merge-queue rules. The scaffold must
supply unconditional PR checks and `merge_group` before queue activation.

The initial published registration commit is a data bootstrap for the supported
synchronizer. A package at that same immutable commit can validate its exact
remote manifest and payloads before installing them into the empty repository.
The published bootstrap pin is
`89bfcebaee8a0fcf99055b2acd1709abb64f8666`. The separately sealed declaration
and source manifest preserve those exact bytes, including all native tests.
This is not deployment approval or a completed fleet release.

Protected main `ee3ae4112834d79c1923a270cb454b87666f62e2` admits only its historical
cohort plus the specifically approved EdgeMech identity. Its strict admission
gate intentionally rejects this additional registration without a separate Assay
declaration. This proposal supplies that independently reviewable declaration. The bounded mechanism proposed in Cofactor onboarding
PR #1056 is a shared implementation dependency; Cofactor's declaration is not
Assay authority. Assay requires its own exact identity, source pin and manifest,
empty-main tip, conservative fleet-entry digest and full native obligations.
No existing DUF/Edge declaration or consumer pin is changed by this proposal.
The exact source object must be authenticated before its data URLs are bound;
later current payloads cannot substitute for its frozen bytes. Assay's separate
pin is never an allowed pin for a historical or Edge consumer. The pending
empty bootstrap state expires at any changed main tip and cannot excuse partial
installation. Candidate policy cannot activate against an older protected base.

Before the onboarding PR is opened, scaffold and separate seed PRs must exist.
Before any merge decision, independently review the proposed Assay declaration,
fix findings, re-review the exact head and require green checks. Only the user's
protected merge can activate admission; a candidate PR cannot approve itself.
Refresh against current main and concurrent admissions before release. Shared
capability promotion, coordinated re-pins, completed-ledger removal, remote
queue activation and the X-Mech Suite projection remain separately reviewed
release work. Existing consumer repositories are outside this PR's mutation
scope.

Seed assay identities from an exact METPO release or commit, preserving the
ontology's distinctions between assay methods and measured outcomes. Initial
scope includes microbial characterization and CMM bioprocessing,
biotransformation and bioaccumulation measurements. Link to an actual CMMMech
record only when its identifier and relation are verified at an immutable
source commit. A chemical association alone does not establish assay validity,
experimental performance or an organism-specific result.
