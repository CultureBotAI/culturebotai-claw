# Phase 2: CultureMech per-media HTML pages + shared QC dashboard

**Status:** Draft
**Audience:** CultureMech maintainers; secondary MIM
**Date:** 2026-05-01
**Source pattern:** dismech `src/dismech/templates/disorder.html.j2` + `src/dismech/render.py` + `dashboard/index.html`

## Goal

Make CultureMech's 10,657 culture-media records **directly browsable as
HTML** (one page per medium) and produce a periodic QC dashboard
showing curation gaps. CultureMech today has only an empty `dashboard/`
directory and a 15 MB monolithic `app/data.js` faceted browser — there
are no per-record pages, no detail views, no curation-health view.

This is the highest-visibility user-facing improvement; once shipped,
each media recipe gets a stable URL, ingredient links to MIM, organism
links to NCBITaxon, and a "view source YAML" link to git.

## Scope

**In scope:**
- Jinja2 per-media templates rendered to `pages/media/{medium_id}.html`
- A `kg_microbe.qc` shared package (extracted from dismech) that
  produces matplotlib + HTML dashboards
- CultureMech-specific QC config (slot coverage thresholds for media)
- GitHub Actions workflow auto-regenerating pages on YAML push
- Static deploy via GitHub Pages

**Out of scope:**
- MIM/CommunityMech adoption (this phase is CultureMech-first; MIM port
  in Phase 5)
- Live (server-rendered) views — static pages only
- Search/UMAP improvements to existing `app/` browser (separate effort)

## Per-media page structure

Match dismech's structure section-by-section, retitled for media:

```
<h1>{{ medium.label }} ({{ medium.id }})</h1>

<section id="overview">
  - Source database (MEDIADIVE / TOGO / DSMZ)
  - Medium type (bacterial/fungal/archaeal/community)
  - Sterilization method
  - pH, temperature, anaerobic flag
  - Use count (N organisms cultured on this medium)
</section>

<section id="ingredients">
  Table: ingredient | concentration | unit | MIM link | CHEBI link
  (each row links to MIM/{slug}.html in Phase 5; for now to MIM SSSOM)
</section>

<section id="organisms">
  Table: NCBITaxon ID (linked to OLS) | label | strain
</section>

<section id="preparation">
  Ordered list of prep steps (if present)
</section>

<section id="evidence">
  (Phase 1 dependency — empty until evidence schema is populated)
</section>

<section id="provenance">
  - View source YAML on GitHub
  - Last curation timestamp + curator
  - Cross-references to BacDive / DSMZ / MediaDive
</section>
```

## Shared QC dashboard package

Extract dismech's QC logic into a repo-agnostic Python package so both
CultureMech and MIM (Phase 5) can use it:

```
culturebotai-claw/src/kg_microbe_qc/
├── __init__.py
├── slot_coverage.py      # walks YAMLs, counts non-null slots per file
├── config.py             # loads conf/qc_config.yaml
├── chart.py              # matplotlib comparison + trend charts
├── render.py             # Jinja2 dashboard.html.j2 → static HTML
└── templates/
    └── dashboard.html.j2 # styled HTML wrapper
```

Each downstream repo provides its own `conf/qc_config.yaml` defining
which slots matter and what thresholds count as "compliant".

## Execution order

1. **Extract QC package** to claw: copy dismech's QC code, generalize
   the YAML walker (currently dismech-specific in `dashboard/` script),
   publish under `culturebotai-claw/src/kg_microbe_qc/`. Add unit tests.
2. **CultureMech QC config**: write `conf/qc_config.yaml` with media
   slot thresholds. Wire `just gen-dashboard` recipe to call
   `python -m kg_microbe_qc.cli --config conf/qc_config.yaml`.
3. **Page template**: port dismech's `disorder.html.j2` line-by-line,
   adapting field names (e.g. `phenotypes` → `ingredients`). Style
   minimally — Bootstrap or vanilla CSS, no JS framework.
4. **Render driver**: `src/culturemech/render.py` — walks `kb/media/`,
   renders each YAML through the template, writes to `pages/media/`.
   Idempotent; only regenerates if YAML mtime > HTML mtime.
5. **Index pages**: top-level `pages/index.html` linking by source-db
   bucket and an alphabetical-by-label list (media count per source).
6. **GitHub Action**: `generate-pages.yaml` triggers on push to
   `kb/media/*.yaml`, runs `just gen-pages` + `just gen-dashboard`,
   opens auto-PR with stats (page count delta, dashboard hash).
7. **GitHub Pages deploy**: enable on the `gh-pages` branch (or use
   actions/deploy-pages); URL is `https://<org>.github.io/CultureMech`.

## Verification

After step 4:
- 10,657 HTML files exist under `pages/media/`
- Random 5 samples open in browser; ingredients link out, organisms

After step 7:
- Pushing a YAML edit triggers the workflow; auto-PR adds the
  regenerated HTML; pages live within 5 minutes of merge.

## Why CultureMech first (not MIM)

CultureMech has the most records (10,657) and the lowest current
discoverability — pages have the highest leverage there. MIM already
has Jekyll + faceted browser; its detail pages are a Phase 5 polish
item, not Phase 2 critical path.
